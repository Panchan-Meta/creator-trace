トップ・利用開始・ログイン

Passkeyで本人確認し、案件作成から利用を始めます。

S01トップページ

/誰でも

サービスの概要と利用開始の入口。

  • 制作物・版管理・納品証跡の概要を表示
  • 無料利用、導入相談、案件管理へ移動
  • 制作チーム向け支援サービスの紹介

ログイン後もトップページを開けます。

S02新規利用登録

/signup未登録の利用者

表示名と最初の案件を登録して利用を開始。

  • 表示名・最初の案件名を入力
  • Passkeyの新規登録
  • 登録後は案件一覧へ移動

一般登録はサーバーのSIGNUP_ENABLED設定に依存。案件作成者は自動的にOWNERになります。

S03ログイン

/login登録済みの利用者

登録済みPasskeyで本人確認。

  • Passkey認証
  • 認証後に案件一覧へ移動
  • 招待経由では案件・招待先・Roleを表示し、認証後に招待画面へ戻る

/login?invite={token} は招待用のログイン導線。初めての利用者には招待Passkey登録へのリンクを表示。

初期設定・招待参加

招待先本人が表示名を決めて案件に参加します。

S04初回アカウント設定

/setup管理者から初期設定情報を受け取った利用者

管理者が作成したアカウントの初期設定。

  • ユーザーID・初期設定トークンを入力
  • 初期設定セッションを取得
  • 認証設定へ移動してPasskeyを登録

一般の新規利用はS02、招待での新規参加はS06を使用。トークンは資料や公開URLに載せません。

S05案件への招待・参加

/invite/{token}招待URLを受け取った利用者

招待内容を確認して案件に参加。

  • 案件名・招待先・Role・状態・有効期限を表示
  • 未ログイン時は新規Passkey登録／既存アカウントのログインを選択
  • ログイン済みなら表示名を決めて参加
  • 参加完了と案件へのリンクを表示

期限切れ・取消・使用済み・アーカイブ案件の招待では参加を停止。表示名はアカウント全体に適用。

S06招待からのPasskey登録

/invite/{token}/signup有効な招待を持つ未登録の利用者

新しいアカウントとPasskeyを作り、招待案件へ参加。

  • 招待内容を表示
  • 表示名を入力
  • Passkey登録後に招待を受諾
  • 参加済みの案件詳細へ移動

登録済み利用者向けのログインリンクあり。ログイン済みの場合はS05へ移動。

案件の管理

案件詳細が、制作物登録とメンバー管理の入口です。

S07案件一覧

/projectsログイン済み利用者

参加中の案件を探し、新しい案件を作成。

  • 自分が参加する非アーカイブ案件の一覧
  • 案件名・クライアント名の検索
  • 前へ／次へのページ移動
  • 案件名・クライアント・開始日・終了日を入力して作成

次ページの実データがある場合だけ「次へ」を表示。ページ移動で検索条件を維持。作成者はOWNERとして自動登録。

S08案件詳細

/projects/{projectId}案件の有効なメンバー

案件情報、制作物、参加者をまとめて管理。

  • クライアント・制作期間・案件内Roleを表示
  • 制作物の検索・ページング・詳細への移動
  • メンバー一覧、過去メンバー・取消履歴を表示
  • 新しい制作物の登録フォームと上部アンカー
  • OWNER／MANAGER：招待作成・URLコピー・招待中一覧・最新3件の招待履歴・取消
  • OWNER／MANAGER：案件名・クライアント・説明の編集、アーカイブ、監査ログ
  • OWNER：OWNER以外のメンバーを外す

担当者の手入力追加フォームは廃止。既存の担当者・制作者データは履歴表示と選択肢に保持。招待メールは自動送信されず、作成直後のURLを手動共有。

制作物の管理

修正版は既存Versionを上書きせず、新しいVersionとして登録します。

S09制作物一覧

/assetsログイン済み利用者

参加案件の制作物を横断して探す。

  • 制作物名・所属案件・最新Version・最新版ファイル名を表示
  • 制作物名、ファイル名、SHA-256、既存制作者名で検索
  • 前へ／次へのページ移動
  • 制作物詳細や案件からの登録へ移動

非アーカイブ案件・制作物を対象に表示。次ページがない場合は「次へ」を非表示。

S10制作物詳細・Version履歴

/assets/{assetId}案件の有効なメンバー

制作物の履歴を確認し、修正版を追加。

  • 制作物名・最新Version・最新版ファイル名を表示
  • Versionごとのファイル情報、状態、SHA-256、コメントを表示
  • Version詳細・証跡詳細へ移動、履歴の検索・ページング
  • 権限に応じて状態変更、AIレビュー、納品・受領を操作
  • Reviewerコメントの閲覧／REVIEWERによる追加
  • OWNER／MANAGER／CREATOR：修正版の登録
  • OWNER／MANAGER：制作物のアーカイブ

修正版は新しいVersionとProofとして追加。CREATORの修正版追加は自分が登録した制作物に限定。機能の詳細はS11参照。

原本ファイルの扱い

制作物登録・修正版登録・照合では、ファイル本体をサーバーに送信・保存しません。ブラウザー内でSHA-256を計算し、ファイル情報とhashを登録します。原本はDrive等で保管し、資格情報・クエリ・フラグメントを含まないHTTPS URLを保存先として指定します。

Version・Proofの詳細

Version → そのVersionのProof → 既存OTS → Bitcoinの順で確認します。

S11Version詳細

/assets/{assetId}/versions/{versionId}案件の有効なメンバー

指定したVersionのファイル情報・履歴・証跡を確認。

  • 状態・ファイル名・サイズ・MIME・登録者・制作者・登録日時・SHA-256・変更内容を表示
  • 提出・承認・差戻し・FINAL確定と状態／承認履歴の表示
  • 5人のBotによるAI制作レビューの実行・最新結果表示
  • 原本の外部保存先URLを開く
  • FINALの納品記録と、指定受領者による受領／受領差戻し
  • Reviewerコメントと対象Versionへのリンク
  • そのVersion自身のOTS・Bitcoin情報表示と証跡作成／再確認

旧Version・FINALでも証跡再確認は可能。FINALのファイル情報・SHA-256は変更しません。AIレビューは参考情報で、承認や状態変更を自動実行しません。

S12証跡詳細

/proof/{proofId}案件の有効なメンバー

特定Proofのファイル照合と外部証跡を確認。

  • SHA-256・ファイル登録日時を表示
  • 手元のファイルを端末内でハッシュ計算して照合
  • OTS作成日時、Bitcoin状態・確認日時・高さ・hash・採掘日時・最終確認処理日時を表示
  • 既存OTSをダウンロード
  • OWNER／MANAGER：証跡作成／再確認、Bitcoin再確認
  • Versionへ戻る、照合画面へ移動、公開対象なら公開Verifyへ移動

ファイル一致とBitcoin確認は別々に判定。再確認は選択Proof自身のOTSを使用し、他VersionのProofへ置き換えません。

ファイル一致とBitcoin確認を分けて確認します。

S13ファイルと証跡の確認

/proof/{proofId}/check案件の有効なメンバー

照合用導線から同じProofを確認。

  • S12と同じSHA-256ファイル照合とBitcoin情報の表示
  • OTSダウンロードと権限に応じた再確認

独立した別の証跡ではなく、S12と同じProofを表示する画面。ファイル本体はアップロードしません。

S14公開確認（Verify）

/verify/{proofId}公開対象Proofは誰でも

指定された公開証跡を第三者が確認。

  • 公開対象のSHA-256・登録日時・OTS／Bitcoin情報を表示
  • 手元のファイルとのSHA-256照合
  • 公開OTSのダウンロード

公開対象は設定で明示したProofのみ。通常の案件証跡は自動公開されず、非公開IDは未認証アクセスで404。再確認操作は提供しません。/verify/{proofId}/checkも同じ表示に対応。

  • 複数登録時にPasskeyを削除
  • APIキー設定へのリンク

最後のPasskeyの削除ボタンは表示しません。APIキー設定リンク先の画面は未実装（P11参照）。

案件Roleと管理者権限

OWNERは案件作成者。MANAGERは案件管理、CREATORは制作物登録、REVIEWERは承認・コメント、VIEWERは閲覧を担います。

ADMINはサイト全体の問い合わせ管理権限です。ADMINであること自体が、案件のOWNER権限を意味するわけではありません。

利用フロー・実装上の補足

履歴と証跡を保持しながら、案件から納品・検証へ進みます。

制作物の基本フロー

案件作成 → メンバー招待 → 制作物登録 → 提出 → 承認 → FINAL → 納品 → 受領

状態はDRAFT → SUBMITTED → APPROVED → FINAL。提出時の差戻しはREJECTEDとして履歴に残り、修正版を別Versionとして追加します。

証跡の確認フロー

OTS_CREATED：OTS作成済み ／ WAITING_BITCOIN：Bitcoin証明待ち ／ BITCOIN_ANCHOR_FOUND：アンカーあり・チェーン未検証 ／ CONFIRMED：検証成功 ／ VERIFY_FAILED：明確な検証エラー。

表示/APIの状態とDB値には対応関係があります。確認成功はverification.state＝BITCOIN_VERIFIED、bitcoin_status＝CONFIRMED。未確認のDB値はPENDING等。Bitcoinアンカー待ちは失敗扱いにせず、既存OTSのupgradeを再試行します。

一覧に含めない機能・実装上の補足

APIキー設定： /settings/api-keys へのリンクはありますが、対応する画面の実装がありません。API側にはキー一覧・作成・失効処理がありますが、利用可能な画面としては数えていません。

監査ログ： APIは案件メンバーに閲覧権限がありますが、現行画面の表示はOWNER／MANAGER向け管理領域内です（最新100件）。

APPROVER： 一部表示コードに残っていますが、現行の招待Role・API権限は上表の5種類です。独立した現行Roleとしては扱いません。

履歴保護： アーカイブやメンバー取消では過去データを削除しません。VersionごとのProof・SHA-256・OTS・作成日時・承認・納品履歴を保持します。

本資料は現行実装の整理であり、全画面を本番ログインで再操作した検証記録ではありません。未実装リンクやAPIとUIの表示差は上記のとおり区別しています。
